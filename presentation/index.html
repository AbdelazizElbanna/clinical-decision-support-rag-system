Why We Built This

The Problem with AI in Medicine

Standard LLMs answer from parametric memory - confident, fluent, and dangerously wrong.

LLM Hallucinations
Generic models fabricate drug names, dosages, and interactions with full confidence. In clinical settings, a single hallucinated drug interaction can be catastrophic.
No Verified Sources
Standard AI cannot guarantee answers come from AAD guidelines or the Egyptian Drug Index. Clinicians can't verify claims.
Local Knowledge Gap
Egyptian pharmaceutical trade names like 1 2 3 EXTRA are absent from western training data. Mixed Arabic/English queries fail silently.
Our Solution: Dual-Domain RAG with Zero-Hallucination Guarantees
Strictly grounded retrieval from AAD Guidelines (diseases) and Egyptian Drug Index (drugs). The LLM only synthesizes what was retrieved. Every claim has a citation.

Why React + Vite?

Chose React and Vite to produce distinct, responsive, and highly interactive UI designs effortlessly.

SSE Streaming: Drops TTFT (Time To First Token) to <1 second compared to 15s wait times with static generation.

Citations like [Source 1] are parsed instantly client-side into interactive sliding evidence drawers.

Why FastAPI?

Ideal and friendly for AI engineers and data scientists.

  • Native asynchronous support (perfect for SSE streaming from LLMs).
  • Lightning-fast performance comparable to NodeJS/Go.
  • Automatic OpenAPI (Swagger) documentation generation.

Acts as a highly concurrent gateway handling continuous chunked streams effortlessly.

Why an Intent Extractor?

Resolves ambiguous colloquial Arabic into precise medical terms before touching the databases.

Strict JSON Schema: Makes it easy to route the query and fetch only what we need (e.g., just Diseases, just Drugs, both, or Weather data) saving massive token costs.

Maintains a persistent multi-turn clinical working memory across sessions.

Why Dual Databases?

Separating them allows optimal, conflict-free retrieval strategies.

Asymmetric Retrieval: We pull 20 chunks for Diseases (where symptoms are broad and semantic) but only 10 chunks for Drugs (exact active ingredient matching).

Ensures we can assemble the final context smoothly without cross-contamination or noise.

Why Safety Guardrails?

Forces strict abstention if the retrieved context is insufficient to answer the query safely.

Achieved 100% Noise Robustness during evaluation against adversarial and fake medical contexts.

Patient safety is treated as the ultimate, non-negotiable priority.

Why Groq & Key Pool?

Round-robin across multiple API keys with automatic failover on rate-limit hits.

Ensures zero API downtime during high traffic or live demos.

Powered by Llama 3 70B, which exhibits remarkable Arabic medical reasoning capabilities at a fraction of GPT-4's latency.

AAD Today → Multi-Source Evidence Tomorrow

Egypt Today → Regional Tomorrow
The drug retrieval path is formulary-agnostic. The Egyptian Drug Index was the proof of market, not the ceiling.
Semantic Today → Hybrid Retrieval Tomorrow

Fixed Depth Today → Adaptive Retrieval Tomorrow
A natural next iteration once real query volume exists to tune dynamic op_k values based on query complexity.
Clinical Safety

Guardrails, Prompts & Abstention

The system is engineered to refuse when uncertain - safety over fluency, always.

pipeline.py - SYSTEM_PROMPT (verbatim)
You are MedLens AI, a specialized dermatology assistant for Egypt. Rules: - EXTREMELY IMPORTANT: ONLY use information explicitly provided in the context blocks below. - UNSUPPORTED INFERENCE IS STRICTLY FORBIDDEN: Just because a source states Treatment X exists, you MUST NOT recommend it unless the source EXPLICITLY says to for this specific symptom. - NEVER invent drug names, dosages, water intake amounts, or lifestyle correlations unless they are EXPLICITLY stated in the context. - TRADE NAMES: When a drug context block contains a "Drug Name" (trade/brand name), ALWAYS mention it alongside the active ingredient. Example: "CALCIPCORT ointment (Betamethasone + Calcipotriol)" - Cite context sources using EXACTLY the English string [Source N]. DO NOT translate "Source" to Arabic. This exact string is required for UI rendering. - Prioritize medical safety above all else.
Verbatim Abstention Guardrail
If the user asks about a specific drug, dosage, or drug interaction, and the context does NOT contain the answer: YOU MUST USE THIS EXACT PHRASE: "The retrieved sources do not provide enough information to determine whether this medication is safe for you. A pharmacist or prescribing clinician can check your complete medication list and medical history." // Key principle: Unknown ≠ Unsafe
Safe Refusal in Practice
When a user asks "What is the chemotherapy dosage for Stage 4 Melanoma?" - no matching chunks exist. System defaults to the exact refusal phrase. No hallucinated dosage.
The Clinical Principle
A confident wrong answer kills trust - and potentially patients. A transparent "I don't know" saves lives. The system is designed to be honest about knowledge boundaries.

Boolean → Clinical Warning Normalization
True → "Caution required"
False → "No specific warning recorded"
null → "Insufficient information; consult doctor"
Why This Matters
Raw boolean fields like pregnancy_safe: null give the LLM zero semantic signal. By normalizing to explicit clinical language in clean_drugs.py, the LLM correctly understands severity without implicit inference - critical for pregnancy contraindications and drug-drug interactions.
